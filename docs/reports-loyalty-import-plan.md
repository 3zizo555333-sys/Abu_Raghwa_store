# خطة استيراد التقارير والولاء والكتالوج

## مبدأ عدم الفقد

لا تُحوّل بيانات `localStorage` مباشرة إلى Supabase ولا تُفرغ مفاتيح المتصفح عند النشر. تُحفظ نسخة JSON للقراءة فقط، ثم يُنفذ `dry-run` يعرض عدد السجلات والتكرارات والأخطاء قبل أي إدخال. لا تُستبدل سجلات موجودة؛ يستخدم الاستيراد مفاتيح `(shop_id, customer_code)` ومعرفات المصدر القديمة كمرجع idempotency.

## ترتيب الاستيراد

1. المنتجات أولاً، مع إنشاء خريطة `legacy product id -> products.id`.
2. التركيبات ثم `recipe_ingredients` بعد حل مراجع المنتجات/المواد الخام.
3. عملاء الولاء بعد تطبيع الهاتف والكود وإزالة الفراغات وتوحيد حالة الأحرف.
4. مستويات المكافآت ثم سجلات تسليم الهدايا بعد ربط العميل والمكافأة.
5. الفواتير المكتملة وبنودها، ثم تحديث `current_points` و`total_points_earned` من مصدر موثوق واحد.
6. طلبات الكتالوج بحالة `pending` أو `confirmed` فقط؛ لا تُستورد الطلبات الملغاة كإيراد.

## التحقق والتطهير

- رفض السجلات التي لا تملك `shop_id` أو معرفاً قابلاً للتتبع.
- تحويل القيم الرقمية إلى أرقام غير سالبة، مع تسجيل أي تصحيح في تقرير dry-run.
- تطبيع أرقام الهاتف إلى صيغة ثابتة، وتوليد كود مؤقت واضح فقط عند غياب الكود.
- كشف تعارض الأكواد داخل المتجر وعدم اختيار سجل عشوائياً؛ يُوقف السجل المتعارض للمراجعة.
- التحقق من أن كل `items` في طلب الكتالوج مصفوفة JSON وأن إجماليها غير سالب.
- تشغيل كل دفعة في transaction منفصلة مع سجل نتيجة وعدّادات قبل/بعد.

## الربط الذري

تُنشأ الفاتورة وبنودها وتحديث نقاط العميل في عملية خادمية واحدة. لا تعتمد التقارير على snapshots محلية؛ صفحة `Reports` تقرأ الفواتير والبنود والعملاء والمكافآت والاستردادات وطلبات الكتالوج من Supabase. عند فشل الشبكة لا تُكتب نسخة مؤجلة في المتصفح ولا يُعاد احتساب النقاط تلقائياً.

## المتاجر الفارغة

تُعامل الاستعلامات الفارغة كمصفوفات فارغة مع إجماليات صفرية صريحة، وتعرض الواجهة رسالة «لا توجد بيانات» بدلاً من اعتبار الصفر دليلاً على عدم وجود مبيعات. لا تُنشأ مكافآت افتراضية في قاعدة البيانات ولا تُحذف بيانات جهاز قديم قبل نجاح تقرير المقارنة.

## التحقق بعد النقل

تُقارن أعداد العملاء والمكافآت والاستردادات والفواتير، ثم تُقارن إجماليات الإيراد والنقاط والتكلفة. لا يُعتمد النقل إلا بعد تطابق التقرير أو توثيق الفروقات المقبولة لكل سجل.
